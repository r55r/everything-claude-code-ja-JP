# /learn - 再利用可能なパターンを抽出

現在のセッションを分析し、スキルとして保存する価値のあるパターンを抽出します。

## トリガー

セッション中に重要な問題を解決したときに `/learn` を実行します。

## 抽出対象

以下を探します：

1. **エラー解決パターン**
   - どんなエラーが発生したか？
   - 根本原因は何だったか？
   - 何で修正したか？
   - 類似のエラーに再利用可能か？

2. **デバッグテクニック**
   - 明らかでないデバッグ手順
   - 有効だったツールの組み合わせ
   - 診断パターン

3. **ワークアラウンド**
   - ライブラリの癖
   - APIの制限
   - バージョン固有の修正

4. **プロジェクト固有のパターン**
   - 発見したコードベースの慣習
   - 決定されたアーキテクチャ
   - 統合パターン

## 出力フォーマット

`~/.claude/skills/learned/[pattern-name].md` にスキルファイルを作成：

```markdown
# [説明的なパターン名]

**抽出日:** [日付]
**コンテキスト:** [いつ適用されるかの簡潔な説明]

## 問題
[このパターンが解決する問題 - 具体的に]

## 解決策
[パターン/テクニック/ワークアラウンド]

## 例
[該当する場合はコード例]

## 使用するタイミング
[トリガー条件 - このスキルを発動させる状況]
```

## プロセス

1. 抽出可能なパターンがないかセッションをレビュー
2. 最も価値のある/再利用可能な知見を特定
3. スキルファイルのドラフトを作成
4. 保存前にユーザーに確認を求める
5. `~/.claude/skills/learned/` に保存

## 注意事項

- 些細な修正は抽出しない（タイポ、単純な構文エラー）
- 一度きりの問題は抽出しない（特定のAPI障害など）
- 将来のセッションで時間を節約できるパターンに焦点を当てる
- スキルは焦点を絞る - 1つのスキルに1つのパターン
